# P01 · 索引层与模板填槽（核心模块 Prompt 链）

> 这是比赛要求的"完整 Prompt 链"之一：**提问 → AI 首版 → 哪里错 → 如何收敛 → 落地**。
> 记录的是本项目真实发生的过程（2026-10-28），不是事后补写的故事。

## 1. 我给的上下文（四段式）

```text
[角色] 你是本项目后端工程师。技术栈固定：Python 3.12 + FastAPI + SQLite(FTS5)。禁止引入向量库/ORM/前端框架。
[目录契约] app/core 只做纯函数（可单测）；app/pipeline 允许调用 core；app/service 是事务边界；api 层不写业务。
[接口契约] build_snapshot(con, project_id, path, head_sha) -> dict；search(con, snapshot_id, q, k) -> {results:[{path,start_line,end_line,snippet,score}]}
[禁区] 不许把整仓库塞进模型；单文件 ≤8KB；最多 40 文件；每条检索结果必须带行号
```

## 2. 逐字提问（第一轮）

> "写索引层：把仓库变成可检索的块。要求（1）文件后缀白名单、排除 node_modules/vendor；（2）按 60 行切块、10 行重叠，记住每块的起止行号；（3）用 SQLite FTS5 建倒排；（4）中文查询也要能命中。不要用 jieba，我不想多一个依赖。"

## 3. AI 首版 + 四个真实缺陷

| # | 首版的问题 | 现象 | 我的收敛方式 |
|---|---|---|---|
| 1 | 白名单只按**后缀**过滤 | `go.mod`、`LICENSE`、`.env.example`、`Makefile` 全被漏掉 → 报告"技术栈/配置/许可"三个槽位全是空的 | 增加 `SPECIAL_NAMES` 名单，按**文件名**放行（非后缀） |
| 2 | README 取"第一段" | 取到的是 `![badge](...)` 和 `- **Features**` 列表项，`what` 槽位输出成了功能清单碎片 | 跳过 badge/图片/标题/列表符号，优先正文段落 |
| 3 | 中文查询直接进 FTS | `配置文件在哪` / `如何启动项目` 命中 **0 条**（整串被当成一个 token） | 自写分词：标识符拆分 + CJK 二元切分（`如何启动项目`→`如何/何启/启动/动项/项目`），查询同规则 |
| 4 | 引用行号随手写 `#L1-L3` | `.env.example` 只有 2 行 → 引用回查失败，`cite_resolve_rate` 掉到 89% | 引用上界一律取该块真实 `end_line`（`min(3, chunk.end_line)`），失败即降级灰区 |

## 4. 第二轮 Prompt（收敛后的写法）

> "按上面的问题重写，三条硬规则：① 文件准入看**文件名+后缀**双条件；② 所有中文文本先过二元切分再入索引；③ 任何 `path#Lx-Ly` 必须能在快照里回查成功——先写 `resolve()` 再写生成器，测试先行。"

## 5. 结果（可复现）

- `python -m pytest -q` → **10 passed**
- `python scripts/eval.py` → Recall@5 **10/10**，引用回查 **100%**，槽位命中 10/11 与 6/11
- 落地：见 `git log` 中 `feat(index)` / `feat(rules)` / `feat(pipeline)` 三次提交

## 6. 我的判断（写进技术文档的话术）

AI 首版最大的问题不是"写得不对"，而是**它不会主动怀疑自己的输入质量**：
白名单漏了 `go.mod`，它照样生成一份"技术栈为空"的报告，看上去毫无异常。
所以约束必须落在**契约层**（文件准入规则、行号回查），而不是散落在 prompt 的形容词里。
